# Agent rules
- Process rule: if a change does not touch Monty's chat handling (whatsapp-webhook replies), run only the FREE tests (`free_suite`: reminder-sender and other no-AI tests). Run the QUICK suite (`quick_suite`) only when chat behaviour changes. Run the FULL suite only for big changes (model upgrades, the rebuild switch-overs, changes touching several of whatsapp-webhook / send-reminders / send-family-update / flush-family-updates / handle-school-email / cron jobs). Report results; if anything fails, fix it or tell Matt - never leave it failing silently — why: these paths reach real parents; free tests keep routine checks at zero AI cost.
- Test safety: every Twilio sender calls `blockIfTestPhone` from `supabase/functions/_shared/testGuard.ts`; test families (allowlisted in `test_phone_numbers`, +4470000000xx) are excluded from real runs — why: tests must never reach a real parent or Twilio.
- send-reminders and sunday-lunch-checkin are split into a read-only build and a real/stub delivery; test entry needs MONTY_TEST_SECRET (constant-time) and is audited in `test_entry_audit` — why: the build can be verified without sending.
- Every Claude call reads its model from `montyClaudeModel()` in `supabase/functions/_shared/claudeModel.ts` (env `MONTY_CLAUDE_MODEL`, code default) — why: switching or rolling back the model is one setting change.
- Opt-out is decided in code before the AI (`_shared/optOut.ts`, whole-message/clear-intent matching): STOP/delete requests go into `opted_out_numbers` (keyed by phone, survives account deletion), START removes it; `blockIfTestPhone` checks the opt-out list for every Twilio send, and only Matt's alerts and the direct reply to the parent's own message pass `allowOptedOut` — why: UK GDPR/PECR and WhatsApp policy require stopping instantly everywhere.
- Ops alerts live in `_shared/alerts.ts` (`evaluateClaudeAlerts`, `evaluateDeliveryAlerts`): real-parent bursts only, one per type per hour in `ops_alerts`, worded "Monty system alert (not from a school)", sent free-form to Matt's WhatsApp only inside his 24h window, otherwise kept as `email_pending` on the /admin/tests banner; tests inject a stub sender and `is_test` rows — why: Anthropic auto-reload is off, so alerts are the safety net, and no template or email sender fits yet.
- Function folders with their own `AGENTS.md` (whatsapp-webhook, send-reminders, sunday-lunch-checkin, handle-school-email, monty-test-runner, twilio-status-callback, delete-parent, signup-alerts) — read it before changing files there — why: keeps this file small.

- Every Anthropic call records tokens + estimated USD via `recordAiCost` (`_shared/aiCost.ts`) into `ai_costs` (purpose, family, is_test); /admin/costs reads it — why: one place to see and cut AI spend.
- School-event year-group, opt-in (words + after-15:15 time rule) and same-day marker rules live in `_shared/schoolEventRules.ts` (no imports; the dashboard imports it too) — why: reminders, dashboard and chat must agree.
- "What's on" rules live only in `_shared/whatsOn.ts` (pure `computeWhatsOn` + loaders; `whats-on` function = caller's own family). Opt-in school events (`OPT_IN_WORDS`) stay in the output flagged `optIn`, never sent as reminders. A parent's note/child reminder sharing a topic word (`TOPIC_WORDS` in schoolEventRules.ts) with a reminder-visible school event for the same child/day is folded into that event (`absorbed`, extra `details`); the shadow compare counts absorbed items as present. Reminders use it when `app_settings.whats_on_source`='new'; 'legacy' is the one-setting rollback — why: one set of rules, testable without the database.
- Schools are shown and searched one way: `_shared/schoolLabel.ts` (pure; sign-up, dashboard, chat and alerts) and the `search_schools` RPC (every word must start a word in name/street/town/council/postcode); `schools.town` is the post town from `postcode_district_towns` (loaded by the `school-towns` function from `_shared/postcodeTowns.json`; a trigger fills new rows); URN stays the school identifier — why: several schools share a name, so parents must see street, town and postcode before confirming.
- A child's school changes only through the `change_child_school` RPC (caller's family or service role; clears that child's event_exclusions, keeps the parent's notes/reminders, logs a `school_changed` dedup decision) — why: dashboard and chat changes behave the same and Matt can see every change on /admin/signups.
