# send-reminders rules
- Morning/evening reminder layout lives in `_shared/reminderFormat.ts`: free-form "emoji Child: item" lines only inside the parent's 24h window, else the approved template with a one-line `{{1}}` (no newlines); free-form failure falls back to the template — why: WhatsApp template variables can't hold line breaks and delivery must never break.
- Item source is `app_settings.whats_on_source`, read on every build ('new' → `buildItemsFromWhatsOn` via `computeWhatsOn`; anything else or a read error → legacy code). Family grouping, opt-outs, test-family exclusion, slot claim, sent log and delivery are shared by both paths; 'new' keeps legacy refId formats so the sent log de-duplicates across a switch, and falls back to legacy for a family if its read fails — why: switching or rolling back is one setting and never skips a family.
- Reminder lines are short: `headline()` strips links/emails/phone numbers (10+ digits) and cuts long text at the first sentence/clause, else at a whole word with "…" (`MAX_LINE`); the saved note is unchanged — why: a reminder is a glance, not the full note.
